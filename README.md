# BuildCheck — Сверка строительных документов

AI-сервис автоматической сверки строительных документов: ведомости объёмов работ (ВОР), сметы, договора и актов выполненных работ (КС-2).

🌐 **Демо-стенд:** [https://buildcheck-kg.streamlit.app/](https://buildcheck-kg.streamlit.app/)

---

## 1. Что это решает

В строительстве ведомости объёмов работ, сметы, договоры и акты выполненных работ приходят в разных форматах и структурах. Обычно специалисты технадзора и сметчики сверяют их вручную глазами в Excel или PDF.

Из-за различий в наименованиях («Бетон М300» vs «Бетон В22,5»), разных единиц измерения («100 м²» vs «м²») и объёма документов легко пропустить:
- превышение накопительного объёма по актам над ВОР;
- завышение единичных расценок в акте по сравнению со сметой;
- появление работ в акте, которых не было в утверждённой ВОР;
- подписание актов после окончания срока действия договора.

**Целевые пользователи:** инженеры технадзора, сметчики, заказчики строительства, инжиниринговые компании.

## 2. Ключевой принцип

> **ИИ читает и понимает названия; обычный код считает и проверяет числа.**

- **Детерминированный расчёт:** сравнение объёмов, цен, сумм, нормализация единиц и проверка порогов выполняются строгим кодом (Python / pandas / SQLite). Одинаковый вход всегда даёт одинаковый результат. Модель чисел не считает.
- **Роль ИИ (Gemini):** сопоставление спорных формулировок и пар названий работ, когда стандартные правила и нечёткий поиск (fuzzy) сомневаются, а также объяснение причин расхождений.
- **Работа без ключа (кэш и fallback):** в демонстрационном режиме все ответы модели сохранены в кэше (`LLM_CACHE_ONLY=1`). При отсутствии сети или ключа приложение автоматически переключается в режим правил (`rules_only`) с информационным баннером.
- **Нейтральный тон:** система фиксирует «возможные расхождения» и позиции, «требующие проверки». Окончательное решение всегда остаётся за инженером.

## 3. Архитектура и пайплайн

Данные проходят через многоуровневый конвейер (`src/pipeline.py`):

```
Excel-файлы (.xlsx)
        ↓
1. Ingestion (чтение по шаблонам config/templates.yaml)
        ↓
2. Нормализация (приведение единиц с коэффициентами, нормализация названий)
        ↓
3. Сопоставление позиций (1:1, exact → synonyms → rapidfuzz → Gemini)
        ↓
4. Бизнес-проверки (превышение объёма, рост цены, нет в ВОР, просрочка)
        ↓
5. SQLite Data Marts (position_status, issues_view, run_summary)
        ↓
6. Интерфейс (Streamlit: Загрузка данных, Результаты, Исходные таблицы, Как работает ИИ)
```

Каждое выявленное расхождение строго привязано к первоисточнику: **файл · лист · строка**.

## 4. Разделы приложения

Поток: **загрузка (или демо-набор) → сверка → результаты**. Результат лежит в `st.session_state["run_result"]`, его читают страницы 2 и 3.

1. **Загрузка данных (`/`, `/upload`, по умолчанию):** поля ВОР, акты, смета, договор (только .xlsx, до 5 МБ на файл, до 9 файлов) и три кнопки демо-наборов: базовый, набор 3, набор 4 (их можно скачать zip-архивом). После сверки автоматический переход на «Результаты».
2. **Результаты (`/results`):** шапка (проект, дата прогона, режим, кнопка «Скачать отчёт в Excel») и три вкладки: «Сводка» (метрики, светофор, диаграммы по типам, итоги), «Расхождения» (карточки с фильтрами по важности, типу и названию, у каждой файл · лист · строка), «Позиции» (сверочная ведомость со светофором; HTML/JS-компонент `ui/ledger.py`, данные `ui/ledger_data.py`). Без результата: «Загрузите данные», ссылка на загрузку и кнопка «Запустить на демо-данных».
3. **Исходные таблицы (`/sheets`):** исходные Excel-файлы прогона как в таблице, подсвечены расхождения и сопоставления ИИ (`ui/sheets_view.py`, `ui/sheet_builder.py`). Без результата то же сообщение, что на «Результатах».
4. **Как работает ИИ (`/rationale`):** сравнение режимов с ИИ и без ИИ на эталоне базового демо, роли ИИ и кода, «Где ИИ ошибается»; таблицы и примеры свёрнуты в блок «Подробности».

**База на каждую сессию.** Каждая сверка идёт в своей временной папке (`buildcheck_run_*`: файл `run.db` и копия загруженных файлов, `ui/runner.py`); параллельные посетители друг друга не затирают. Новая сверка удаляет прошлую папку той же сессии, брошенные папки старше 6 часов чистятся при следующем прогоне. Общая демо-база `hackathon_ai_demo` нужна только странице «Как работает ИИ». Демо-наборы берут ответы ИИ только из кэша (ключ не используется).

## 5. Быстрый старт локально

### Требования
- Python 3.11+
- Виртуальное окружение

### Установка и запуск

```bash
# Клонирование и переход в проект
git clone https://github.com/aijamaltab/hackathon_ai.git
cd hackathon_ai

# Создание и активация виртуального окружения
python3 -m venv .venv
source .venv/bin/activate  # На Windows: .venv\Scripts\activate

# Установка зависимостей
pip install -r requirements.txt
pip install -r requirements-dev.txt

# Запуск тестов (380 тестов)
pytest -q

# Запуск веб-приложения
streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

### Живой ИИ на странице «Загрузка данных»

Демо-наборы и «Как работает ИИ» работают только на сохранённых ответах ИИ (`data/cache/llm/`), ключ им не нужен. Загрузка своих файлов при наличии ключа отправляет новые названия в Gemini в реальном времени; без ключа работает на кэше и честно об этом пишет.

- Ключ: Streamlit Cloud, Settings, Secrets: `GEMINI_API_KEY = "..."` (локально `.streamlit/secrets.toml`, файл в `.gitignore`) или переменная окружения `GEMINI_API_KEY`. В код, логи, кэш и сообщения об ошибках ключ не попадает.
- Режим клиента задаётся явно (`LlmClient(cache_only=..., api_key=...)`), окружение во время работы не меняется: процесс на хостинге общий для всех посетителей.
- Лимиты (`ui/live_ai.py`): 25 живых запросов на сессию, 150 в сутки на весь сайт, 90 секунд на прогон, до 9 файлов по 5 МБ, только `.xlsx`. При достижении лимита прогон останавливается, оставшиеся пары остаются неоднозначными, страница показывает, что сделано и что осталось.
- Новые ответы пишутся в `data/cache/llm/` на сервере; их и `_usage.json` в репозиторий не коммитят.

### Дополнительные наборы синтетики

`data/synthetic_sets/set_2` (капремонт детского сада), `set_3` (амбулатория) и `set_4` (дом культуры; ответы ИИ в кэше, цифры в `docs/ai_error_analysis.md`, раздел 10): те же девять файлов и 12 заложенных расхождений, но другие объект, seed и названия работ (`scripts/synthetic_profiles.py`). Генерация: `python scripts/generate_synthetic.py --set set_2`. Оценка: `python scripts/evaluate.py --set set_2 --gemini-cache`. Заполнить кэш ИИ по набору (нужен ключ, запускает человек): `python scripts/run_llm.py --set set_2`. На странице загрузки базовый набор, набор 3 и набор 4 можно скачать zip-архивом или сверить кнопкой (набор 2 остаётся только в репозитории).

## 6. Честные ограничения и оговорки

1. **Синтетические данные:** демо-проект построен на синтетических файлах, воспроизводящих структуру публичных тендеров. Цены являются ориентировочными, а не рыночными.
2. **Оптимистичные показатели сопоставления:** словарь синонимов в демо сформирован по тем же тестовым документам; на реальных документах заказчика потребуется адаптация справочников и шаблонов.
3. **Только Excel (.xlsx):** текущая версия ориентирована на таблицы Excel. Обработка PDF-сканов и сметных форматов (.gsfx/.arp) запланирована на следующие версии.
4. **Система не подтверждает факт работ:** совпадение документов не означает, что работы фактически выполнены на стройплощадке, а расхождение — лишь сигнал для проверки документации человеком.
