# Предложения по изменению схемы данных (один список для обсуждения, не применено)

Схема данных в разделе 7 `CLAUDE.md` — контракт между двумя участницами. `src/db.py` **не меняем**, пока вторая участница не согласится.
После согласия: правим `src/db.py`, раздел 7 `CLAUDE.md`, парсеры и тесты.

## Сводка

| № | Предложение | Таблица | Тип | Нужно для MVP? | Что будет, если не добавлять |
|---|---|---|---|---|---|
| 1 | `quantity_raw` | `items` | TEXT NULL | нет | сырое количество смотрим по `source_file` и `source_row` |
| 2 | `contractor` | `documents` (или `items`) | TEXT NULL | нет | сводки по подрядчику нет, идея остаётся в backlog |
| 3 | `kind` | `items` | TEXT NULL, `work` или `material` | нет, но удобно | `kind` остаётся внутри `work_key`; для фильтра и отображения его приходится разбирать из ключа |
| 4 | `currency` | `documents` | TEXT NULL | нет (для синтетики), нужно для актов в валюте | валюта живёт в staging и в `details` записи dq; проверка «валюты не совпадают» работает, но валюту нельзя запросить из БД |

Ни одно из четырёх предложений не требуется для расчёта на наших синтетических данных: система работает без них. Это удобства для объяснения, фильтрации и backlog.

## 1. `items.quantity_raw TEXT NULL`

**Зачем.** В реальных ВОР количество указано в единицах нормы: «100 м2» и 0,06 означает 6 м2. В `items.quantity` мы кладём уже нормализованное значение (6), а `unit_raw` хранит «100 м2». Чтобы в интерфейсе показать то, что написано в файле («0,06 100 м2»), нужно исходное значение. Сейчас его можно получить только открыв файл по `source_file` и `source_row`.

**Что хранить.** Текст исходной ячейки с количеством как есть, например `"0,06"` или `"12,5"`. Формулу из соседней колонки не кладём (она остаётся в staging).

**Почему nullable.** Для источников, где количества нет (договор).

## 2. `contractor TEXT NULL`

**Зачем.** Backlog-идея: сводка расхождений по подрядчику (`docs/backlog.md`, раздел 4). Реализовывать пока не будем.

**Где хранить.** Рекомендуем `documents.contractor`, а не `items.contractor`: подрядчик указан в договоре и акте один на документ, а не на строку, так данные не дублируются. Альтернатива: `items.contractor`, если нужен фильтр без join.

**Почему nullable.** В синтетике подрядчика нет. Заполнять только из загруженных документов; привязку подрядчиков к участкам (устная информация, не проверено) в данные не закладываем.

## 3. `items.kind TEXT NULL` (`work` | `material`)

**Зачем.** Материалы отдельными строками («Кабель ВВГнг 3×2,5» после работы «Прокладка кабеля») не должны суммироваться с работой: иначе 24 × 100 + 2 400 даёт 4 800 м вместо 2 400. Правила в `docs/synthetic_spec.md`, §6. Сейчас `kind` входит в ключ: `work_key = kind + нормализованное название + единица` (формат в `rules.yaml`, `matching.work_key_format`), поэтому схема не меняется и MVP работает без колонки.

**Что даёт колонка.** Фильтр «показать только работы», отображение «материал» в интерфейсе и более простые SQL-запросы без разбора префикса ключа.

**Значения.** `work` или `material`. Если kind не удалось определить, ставим `work` и пишем запись в `dq_checks` (`check_name = "kind не определён"`). При добавлении колонки можно добавить `CHECK (kind IN ('work','material'))`.

**Почему nullable.** Для `contract` kind не применим.

## 4. `documents.currency TEXT NULL`

**Зачем.** У реального акта (образцы получены не с портала, `docs/real_templates_findings.md`, раздел 4) валюта указана только в тексте заголовка колонок цены и суммы (USD), а смета у нас в сомах. Сравнивать цены и суммы в разных валютах нельзя, поэтому при несовпадении валют проверки цены и суммы не выполняются (`docs/synthetic_spec.md`, §6, «Валюта»). Для этого валюту нужно знать на уровне документа.

**Что хранить.** Одна валюта на документ, берётся из заголовка колонки цены (`currency_from_header_text` в `templates.yaml`). По умолчанию «сом» для наших синтетических документов, где валюта не указана. Конвертации валют нет.

**Почему `documents`, а не `items`.** Валюта одна на документ, в строках её не дублируем.

**Почему nullable.** Если валюту определить не удалось, поле остаётся пустым, а в `dq_checks` пишется запись.

**Пока не согласовано.** До решения команды валюта хранится в staging и в `details` записи dq. Схему и `CLAUDE.md` §7 не меняем.

## Что не меняется

- Таблицы `matches`, `issues`, `dq_checks`, `runs` остаются как есть.
- Светофор (`position_status`) и влияние на бюджет (`impact_som` в `issues_view`) считаются **во view**, отдельных колонок и таблиц не требуют (`docs/synthetic_spec.md`, разделы 6 и 7).
