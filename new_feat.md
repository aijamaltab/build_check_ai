# Спецификация: Интерактивный UI исходных данных (Google Sheets Lookalike)

**Цель:** Создать экран детального аудита исходных документов в виде табличного процессора (Google Sheets Lookalike) с возможностью визуальной трассировки найденных расхождений между документами (ВОР ↔ Смета ↔ Акты).

---

## 1. Концепция и UX-требования

1. **Эстетика табличного процессора:**
   - 2D-сетка документа с координатными заголовками строк (`1, 2, 3...`) и столбцов (`A, B, C...`).
   - Верхняя панель: активный адрес ячейки (например, `C14`) и формула/значение в строке `fx`.
2. **Светофорная подсветка рисков:**
   - 🔴 **Красный:** Критические расхождения (превышение объёма ВОР, завышение расценки сметы, появление работы без ВОР).
   - 🟡 **Жёлтый:** Предупреждения (несопоставленные позиции низкой уверенности, сдвиги сроков).
   - 🟢 / 🟣 **Нейтральный/Информационный:** Совпадение без расхождений / «Сопоставлено ИИ».
3. **Интерактивный поповер (Tooltip / Popover):**
   - Клик по подсвеченной ячейке открывает модальное окно/поповер с аудитом: план vs факт, $\Delta$, влияние на бюджет в сомах.
   - **Кнопка сквозного перехода:** прямое перемещение к связанной ячейке в другом документе-первоисточнике.
4. **Нижняя панель вкладок (Sheet Tabs):**
   - Переключение между загруженными файлами объекта (ВОР, Смета, Акт №1, Акт №2).
   - Бейджи-счётчики рисков на каждой вкладке (например, `Акт №1 [ 3 🔴 | 1 🟡 ]`).

---

## 3. Декомпозиция задач (WBS / Tasks)

### Этап 1. Подготовка и аннотирование данных (Backend)

- [x] **Task 1.1: Экстрактор сырой сетки документа (`src/ui/sheet_builder.py` / `ui/sheet_builder.py`)**
  - Реализован парсер файла через `openpyxl` (режим `data_only=False` для формул и `data_only=True` для значений).
  - Сформирована матрица ячеек: `row_idx`, `col_idx`, `col_letter`, `formatted_value`, `formula`.
  - Ограничен размер сетки значащими строками и колонками (отсечены пустые хвосты таблицы).

- [x] **Task 1.2: Слой аннотаций расхождений (Mapping Issues → Cells)**
  - Сопоставлены строки `items` и `issues_view` по ключам `source_file`, `source_sheet`, `source_row`.
  - Определена целевая ячейка в строке для подсветки (колонка объёма, цены или наименования работы в зависимости от типа `issue_type`).
  - Сформирована перекрёстная ссылка `linked_ref`:
    - Для акта: ссылка на строку и колонку в ВОР или смете (`target_jump`).
    - Для ВОР: обратная ссылка на строки в актах.

- [x] **Task 1.3: Агрегация статусов и счетчиков для вкладок**
  - Подсчитано количество 🔴 (high severity), 🟡 (low severity / ambiguous) и 🟣 (ИИ) для каждого файла.
  - Подготовлены метаданные для вкладок: название файла, тип документа, счётчики рисков.

---

### Этап 2. Сетка и строка формул (Streamlit + CSS/HTML)

- [x] **Task 2.1: Скелет страницы и строка формул `fx` (`ui/sheets_view.py`)**
  - Создан макет страницы:
    - Контейнер строки состояния ячейки: поле `Cell Address` (readonly) + поле `fx` (формула или текст).
    - Контейнер для скроллируемой сетки таблицы (`overflow: auto`, высота ~65vh).
    - Нижний контейнер для панели вкладок (Sheet Tabs).

- [x] **Task 2.2: CSS-стилизация Google Sheets Lookalike**
  - Серые системные границы: `#e1e3e1`, моноширинные номера строк/колонок с фоном `#f8f9fa`.
  - Стили подсветки:
    - 🔴 `issue-red`: мягкий красный фон (`#FDE8E8`), красный угол-маркер.
    - 🟡 `issue-yellow`: янтарный фон (`#FEF08A`).
    - 🟣 `matched-ai`: фиолетовый индикатор семантического сопоставления.
  - Эффект выделения активной ячейки: рамка `#1a73e8` толщиной 2px.

---

### Этап 3. Интерактивность и сквозной переход (JS / Interaction)

- [x] **Task 3.1: Обработка клика по ячейке и обновление строки `fx`**
  - JS-обработчик клика по ячейкам:
    - Запись адреса (`A1`, `C14`) в поле адреса.
    - Запись формулы/значения в поле `fx`.
    - Добавление класса `.selected-cell`.

- [x] **Task 3.2: Интерактивный поповер расхождения**
  - При клике на ячейку с расхождением показывается всплывающая карточка:
    - Заголовок: Тип расхождения («Превышение объёма», «Завышение расценки»).
    - Данные: Ожидалось (План), Факт (Акт), Разница ($\Delta$), Финансовое влияние в KGS.
    - Примечание: «Сопоставлено ИИ» (при наличии флага матчинга).

- [x] **Task 3.3: Сквозная навигация между документами (Cross-document Jump)**
  - Кнопка в поповере: **«Показать в ВОР»** или **«Показать в Смете»**.
  - Логика перехода по клику:
    1. Автоматическое переключение вкладки на целевой документ.
    2. Позиционирование/скролл к нужной строке (`scrollIntoView({ behavior: 'smooth', block: 'center' })`).
    3. Анимация фокуса целевой ячейки (мигание рамки/фона для акцента внимания).

---

### Этап 4. Тестирование и верификация

- [x] **Task 4.1: Тесты на корректность координат**
  - Проверено, что ячейка с подсвеченным расхождением строго совпадает с исходной строкой в `.xlsx`.

  - Проверено отображение сетки и карточек расхождений при запуске без ключа API (`tests/test_sheets_audit.py`).
